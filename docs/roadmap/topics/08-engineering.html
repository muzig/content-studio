🛠️ 工程化

已知

是什么

本节汇总项目里不属于主流程、但属于工程基础设施的工具：包管理 pnpm、ESLint 代码检查、tsx（用 TS 直接跑 Node 脚本）、dotenv 环境变量加载。

为什么这个项目要用它

pnpm 快、省磁盘；ESLint 兜底代码风格；tsx 让 prisma/seed.ts 这种 TS 脚本能直接 node 跑；dotenv 让 .env 里的密钥进 process.env。

项目里的实际位置：

  • pnpm-workspace.yaml — pnpm workspace 配置
  • eslint.config.mjs — ESLint 9 flat config
  • prisma/seed.ts — 用 tsx 跑的种子脚本
  • .env + src/lib/prisma.ts 里的 process.env.DATABASE_URL

核心概念

1. pnpm

Node 包管理工具，比 npm 快、磁盘省（用 hard link 共享依赖）。本项目所有命令都用 pnpm：

pnpm install              # 装依赖
pnpm dev                  # 启动 Next.js dev server
pnpm build                # 生产构建
pnpm lint                 # ESLint 检查
pnpm db:seed              # 跑 prisma/seed.ts
pnpm roadmap              # 本路线图文档站（serve docs/roadmap）

2. ESLint 9 Flat Config

v9 改用 eslint.config.mjs（ESM 模块），不再是 .eslintrc.json：

// eslint.config.mjs
import { defineConfig, globalIgnores } from "eslint/config";
import nextVitals from "eslint-config-next/core-web-vitals";
import nextTs from "eslint-config-next/typescript";

export default defineConfig([
  ...nextVitals,
  ...nextTs,
  globalIgnores([".next/**", "out/**", "build/**", "next-env.d.ts"]),
]);

继承 Next.js 官方的 React + TS 规则集。

3. tsx — 用 TS 直接跑 Node

普通 Node 只能跑 .js，tsx 包装了 esbuild 让 .ts 直接执行：

# package.json
{
  "scripts": {
    "db:seed": "tsx prisma/seed.ts"
  }
}

本项目用 tsx 跑 prisma/seed.ts（含 Prisma 类型）。

4. dotenv

Node 默认不读 .env，dotenv 在脚本入口处 import "dotenv/config" 即可：

// prisma/seed.ts 顶部
import "dotenv/config";

// 现在 process.env.DATABASE_URL 可用

Next.js 自动读 .env，不需要手动 import。

最小可运行示例

# scripts/print-env.ts
import "dotenv/config";
console.log(`DB: ${process.env.DATABASE_URL}`);

# 跑
npx tsx scripts/print-env.ts
