📘 TypeScript

重点学

是什么

TypeScript 是 JavaScript 的超集，给 JS 加了静态类型。编译时检查类型错误，编辑器（VSCode）能给出精确补全和跳转。

为什么这个项目要用它

本项目 tsconfig.json 开启 strict: true。Prisma 客户端、Next.js API、React Props 全部带类型，能在编译期发现拼错字段名、漏传参数等 bug。

项目里的实际位置：

  • tsconfig.json — 编译器配置
  • next-env.d.ts — Next.js 生成的类型引用（不要手改）
  • src/lib/types.ts — 项目内公共类型
  • src/generated/prisma/ — Prisma 自动生成的类型

核心概念

1. 基础类型注解

let name: string = "alice";
let count: number = 42;
let active: boolean = true;
let tags: string[] = ["ts", "next"];

2. 接口 / 类型别名

interface PlatformRule {
  platform: string;
  label: string;
  style: string;
}

type Result = { ok: true; data: unknown } | { ok: false; error: string };

3. 路径别名 @/*

tsconfig.json 里：

{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}

效果：@/lib/prisma 等价 src/lib/prisma。本项目到处使用：

import { prisma } from "@/lib/prisma";
import { cn } from "@/lib/utils";
import { Button } from "@/components/ui/button";

4. 异步函数返回类型

Next.js 的 params 在 15+ 是 Promise，必须 await：

export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  // id 现在是 string
}

最小可运行示例

type User = { id: number; name: string };

function greet(u: User): string {
  return `Hi ${u.name}`;
}

// 编辑器会报错：greet({ id: 1 })  // 缺少 name
greet({ id: 1, name: "Alice" });
